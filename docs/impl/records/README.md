# Task Records

Task records preserve the work contract and acceptance evidence after a task leaves the
[forward plan](../plan.md). The [current-state index](../current.md) describes available behavior.

Copy the [template](template.md) using the
[record file naming rules](../../guide/planning-workflow.md#record-file-naming). For planned work,
open the record before editing. Task IDs are stable and globally unique. Keep the original task
text and explain any later scope changes in the record. If a task spans multiple sessions, keep
the record open and name the remaining gate and the next action.

For direct requests, use a record when findings, tradeoffs, or verification evidence need a
durable handoff. Link records from the owning current-state page when they explain a durable
decision. A record can name a plan task by ID because plan headings disappear on acceptance.
